# LoreCraft 需求文档 v1.0

> **文字冒险 + LLM 动态叙事 + 无限流世界穿梭 + Roguelite 死亡继承**

---

## 1. 项目定位

**个人原型 / 概念验证项目。** 目标是验证一个核心问题：

> 「LLM 动态叙事 + 代码权威状态机」能否支撑起一个**死亡有痛感、继承有感知**的无限流 Roguelite 文字冒险？

- 不做账号系统、付费、多用户
- 本地部署自玩，API key 由使用者（开发者本人）持有
- 好玩再谈产品化

## 2. 核心概念（术语表）

| 术语 | 定义 |
|------|------|
| **Run（局）** | 从角色创建到死亡的一次完整游戏过程 |
| **世界** | 手写的剧本单元（设定 + 幕表 + flag），玩家在其中游玩 |
| **寿命** | 全局回合预算。每进行一回合消耗 1 点，归零即死亡 |
| **幕表** | 每个世界内的阶段结构（约 3 幕），由 flag 达成推进 |
| **Flag** | 代码权威的布尔型剧情标记（如 `got_bronze_key`），只能由 LLM 申报、白名单校验后生效 |
| **记忆** | 局终由 LLM 从本局经历提炼的文本，注入后续局的 prompt，构成信息优势 |
| **继承层** | 跨局持久的数据：记忆 + 寿命上限 + 世界解锁进度 |
| **枢纽** | 世界之间的中转站界面（纯 UI，不消耗 token），做继承管理与选择下一世界 |

## 3. 核心循环

```
                 ┌─────────────────────────────────┐
                 ▼                                 │
  开局(继承注入) → 枢纽(选世界) → 世界内游玩(回合循环)
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                       通关世界                 死亡
                     (达成主目标)        (寿命/体质/心智归零)
                          │                       │
                     解锁新世界+奖励          记忆提炼(LLM)
                          │                       │
                          └───────────┬───────────┘
                                      ▼
                              结算继承层 → 重开/继续
```

- **回合循环**：玩家输入（自由文本或点选建议行动）→ 后端调 LLM（单次大 schema）→ 代码校验状态申报 → 更新状态 → 渲染叙事
- 一条 run 可以连续穿梭多个世界（寿命池不清零），死亡则整局结束进入继承

## 4. 寿命制（回合经济）

寿命取代传统 roguelite 的"行动点/回合上限"，是贯穿全局的核心资源。

### 4.1 基本规则

- 寿命是一个**全局共享池**：穿梭世界**不清零**
- 每进行一回合消耗 **1 点**
- 寿命归零 → 死亡（寿终正寝，叙事上由 LLM 演绎"油尽灯枯"）

### 4.2 数值框架（初值，全部集中在常量表便于调参）

| 项 | 初值 | 说明 |
|----|------|------|
| 初始寿命上限 | **60** | 新角色起步 |
| 通关世界奖励 | 当前寿命 **+15** | 通关即回血，鼓励推进幕表 |
| 世界内事件增减 | ±1 ~ ±10 | 仙丹/祸福事件，由 LLM 申报（受每回合上限约束） |
| 通关继承成长 | 寿命上限 **+5 / 世界** | 跨局变强的主要数值来源 |

### 4.3 设计意图

- 上限可被继承抬升 → 每局"能走的回合数"越来越多 → 更容易推进幕表
- 「你的时间不多了」的压迫感贯穿整个 run，跨世界省着用还是梭哈由玩家决策

## 5. 局内状态系统

**代码权威**：所有状态由代码持有与管理，LLM 只能通过结构化输出**申报**变更，经校验后生效。

### 5.1 属性（3 项，局内）

| 属性 | 作用 | 归零后果 |
|------|------|----------|
| 体质 CON | 生命/耐力 | **死亡** |
| 心智 MIND | 理智/精神 | **死亡**（神魂俱灭） |
| 敏捷 AGI | 行动/闪避门槛 | 门槛不足时 LLM 叙述失败风险 |

- 初始值各 10，上限 20
- LLM 申报伤害/恢复，代码校验**每回合单项变动 ≤ ±3**

### 5.2 其它局内状态

- **物品栏**：`{名称, 描述}` 简单列表，可携带进下一个世界
- **状态标记**：自由标签（中毒/诅咒/轻伤…），LLM 申报增删，影响其后续叙事倾向

### 5.3 死亡判定（代码权威）

死亡**只能**由以下硬规则触发，LLM 无权直接判死：

1. 寿命 = 0
2. 体质 = 0
3. 心智 = 0

LLM 的 `dangerProposal` 仅用于叙事铺垫与伤害申报（受 ±3/回合 约束），映射不到即死。

## 6. 世界与幕表

### 6.1 世界定义（数据结构）

每个世界是手写的结构化剧本，LLM 只做演绎不做编剧：

```ts
interface WorldDef {
  id: string
  title: string
  theme: string
  intro: string            // 世界观 + 入场背景（注入 LLM）
  systemRules: string[]    // 世界规则（怪谈的"规则"/修仙的门规）
  acts: Act[]              // 阶段幕表（约 3 幕）
  winCondition: {
    requiredFlags: string[]  // 主目标 = 关键 flag 集合，全部达成即通关
  }
  balanceHint: number      // 预期寿命消耗（平衡参考，非硬限制）
  npcs: NpcBrief[]
  dangers: string[]        // 危险源（给 LLM 的编剧约束）
  unlocks: string[]        // 通关后解锁的世界 id
}

interface Act {
  id: string
  title: string            // 如「第一幕：入夜」
  goal: string             // 本幕叙事目标（节奏指引）
  milestoneFlags: string[] // 推进到下一幕所需 flag
}
```

### 6.2 幕表推进

- LLM 每回合被告知**当前幕数与幕目标**，用于控制叙事节奏
- `milestoneFlags` 达成 → 代码推进到下一幕，并通知 LLM 渲染幕转折
- 主目标 `requiredFlags` 全达成 → 通关

### 6.3 首发世界（3 个，标题为工作名）

| 世界 | 题材 | 一句话设定 | 机制验证点 |
|------|------|-----------|-----------|
| 《午夜便利店》 | 规则怪谈 | 深夜便利店夜班店员，墙上贴着必须遵守（或故意打破）的规则 | flag 密集型目标、氛围张力 |
| 《青云门外门》 | 修仙 | 寿元将尽的外门弟子，在宗门大比中搏一线机缘 | 寿命制与题材原生咬合、数值成长叙事 |
| 《风雪山庄》 | 武侠 | 风雪夜困于黑店客栈的过路刀客，江湖恩仇当面了结 | 多 NPC 关系网、自由博弈 |

## 7. 死亡、继承与枢纽

### 7.1 记忆提炼（局终触发，死亡或通关后）

一次独立 LLM 调用，产出：

```ts
interface MemoryExtraction {
  memories: string[]   // ≤5 条，每条 ≤50 字，第二人称
                       // 例：「你记得便利店的第三条规则是假的。」
}
```

- 记忆总量封顶 **20 条**，超出时由 LLM 合并淘汰最旧
- 记忆是**信息优势**：注入后续局 prompt，LLM 被要求在叙事中自然引用

### 7.2 跨局继承（重开一局时）

| 项 | 规则 |
|----|------|
| 局内属性/物品 | **清零**（物品是否带入选为：清零，保持重开节奏干净） |
| 记忆 | 保留（封顶 20 条） |
| 寿命上限 | 只增不减（+5 / 已通关世界） |
| 世界解锁 | 永久保留 |

### 7.3 枢纽（纯 UI，不花 token）

- 展示：当前寿命/上限、记忆列表、已解锁世界、死亡历史
- 操作：选择下一个世界进入、开始新 run
- 无叙事化主神（token 与可控性考虑，留给 v2+）

## 8. 交互设计

- **主输入**：自由文本打字（LLM 动态叙事的灵魂）
- **辅助输入**：LLM 在同一回合的结构化输出中附带 **2-3 条建议行动**按钮，点选即发送，零额外 token
- 叙事渲染：流式输出，中文，每回合约 200-500 字
- 状态侧栏：寿命条、三项属性、物品、当前幕数

## 9. LLM 架构

### 9.1 调用结构：单次调用大 schema

一回合 = **一次** LLM 调用（API 原生结构化输出/工具调用保证 JSON 合法）：

```ts
interface TurnOutput {
  narrative: string              // 本回合叙事
  stateChanges: {
    attributeDelta?: { con?: number; mind?: number; agi?: number }  // 校验 ±3/回合
    lifespanDelta?: number       // 校验 ±10/回合，通常为 0
    itemsGained?: Item[]
    itemsLost?: string[]
    statusTagsGained?: string[]
    statusTagsRemoved?: string[]
  }
  flagsAchieved?: string[]       // 只能是世界定义中声明的 flag id（白名单校验）
  suggestedActions: string[]     // 2-3 条
}
```

### 9.2 代码校验（全部申报过三关）

1. **范围校验**：数值变动不超每回合上限
2. **白名单校验**：flag 必须存在于当前世界定义
3. **合法性校验**：失去的物品必须在持有列表中，等等

### 9.3 降级策略

- schema 校验失败 → **自动重试 1 次**
- 再失败 → 降级为「环境回合」：叙事照常渲染，状态不变，游戏不中断，记录日志

### 9.4 上下文管理

- **局内**：滚动摘要——每 N 回合（建议 10）将早期历史压缩为摘要，控制 token 增长
- **跨局**：只注入提炼后的记忆（≤20 条）与世界设定，绝不注入原始历史
- 每回合请求 = 系统提示（GM 角色 + 世界设定 + 当前幕）+ 状态快照 + 近期历史/摘要 + 玩家输入

### 9.5 Provider 抽象

- 统一接口：`chat(messages, schema) → structured output`
- **默认**：国产模型（DeepSeek），中文叙事好、成本低（约 ¥1-4/百万 token）
- **可切换**：Claude，用于验证叙事质量上限
- key 存服务端 `.env`，前端永不接触

## 10. 系统架构与技术栈

```
lorecraft/                  # pnpm monorepo
├── apps/
│   ├── web/                # Vue3 + TS + Vite —— 游戏前端（枢纽、回合界面、状态侧栏）
│   └── server/             # Node + Hono（极薄层）—— LLM 代理、规则校验、存档 CRUD
├── packages/
│   ├── core/               # 游戏状态机 + 规则引擎 + 校验逻辑（前后端共享同一份类型与实现）
│   ├── worlddata/          # 世界库：3 个世界的结构化定义
│   └── llm/                # provider 抽象 + prompt 模板 + schema 定义
└── docs/
```

- **存储**：SQLite（`better-sqlite3`），表：`runs`（局内快照）、`meta`（继承层）、`logs`
- **选型理由**：游戏状态机 / LLM schema / 世界库结构前后端必须共享，同语言直接 import 同一份类型，避免双写漂移
- 服务端 API（示意）：`POST /api/runs`、`POST /api/turn`、`POST /api/runs/:id/settle`（死亡/通关结算）、`GET /api/meta`、`GET /api/worlds`

## 11. v1.0 范围与验收标准

### 11.1 范围

3 个世界（6.3）+ 完整循环：开局 → 枢纽选世界 → 游玩 → 通关/死亡 → 记忆提炼 → 继承 → 重开。

### 11.2 验收标准

1. ✅ 一条 run 能**跨 ≥2 个世界**（寿命池共享且被正确扣减）
2. ✅ 死亡继承在下一局**叙事中被明确感知**（记忆被 LLM 自然引用）
3. ✅ 完整循环跑通：含通关线与死亡线
4. ✅ 三种死亡（寿命/体质/心智归零）都能触发并正常进入继承流程
5. ✅ LLM 输出异常时游戏**不崩溃**（重试+降级路径生效）
6. ✅ 寿命上限继承可见：通关世界后，新 run 起始上限 +5

## 12. 明确不做（Non-goals）

- 账号系统、付费、多用户
- 内容审核与安全合规（个人自玩）
- LLM 动态生成世界（v1.0 世界全部手写；变体生成留 v2+）
- 骰子/检定规则引擎（属性仅作门槛与资源，不做 COC 式判定）
- 移动端原生、语音、图片生成、多人
- i18n（仅中文）

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| LLM 不遵守 schema / 乱申报 | 三关校验 + 重试 1 次 + 环境回合降级 |
| 叙事质量方差大 | Provider 可切换，用 Claude 验证上限；prompt 迭代集中在此 |
| 寿命/数值失衡（世界过难/过易） | 全部数值集中常量表；每个世界有 `balanceHint` 供对照实测 |
| 成本失控 | 记录每局 token 消耗日志；默认便宜模型 |
| LLM 注水拖回合 | 寿命制天然惩罚注水；幕表节奏由代码 flag 推进而非 LLM 自评 |

## 附：关键决策记录（2026-10-10 grilling 会议）

1. 定位 = 个人原型，验证核心循环
2. 世界 = 内置剧本库，LLM 只演绎
3. 继承 = 叙事记忆 + 寿命上限/解锁数值
4. 局内状态 = 轻量数值层，代码权威
5. 死亡判定 = 代码权威（数值归零），LLM 无判死权
6. 穿梭 = 轻量枢纽（纯 UI）+ 自选世界
7. **寿命制** = 全局共享回合池，上限可被事件与继承抬升（取代固定回合上限）
8. 重开 = 局内清零，只带继承层
9. 交互 = 自由文本 + 建议行动按钮
10. LLM = 单次调用大 schema，结构化输出
11. 模型 = Provider 抽象，默认 DeepSeek，可切 Claude
12. 形态 = 轻后端 Node + Vue3 前端，pnpm monorepo + SQLite
13. 范围 = 3 世界全循环（规则怪谈/修仙/武侠）
14. 验收 = 跨 ≥2 世界 + 继承被叙事感知
