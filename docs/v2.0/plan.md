# LoreCraft v2.0 执行计划 —— 江湖一生

依据：`docs/v2.0/requirement.md`（背景与全部产品决策）

评估日期：2026-10-11
状态：可进入实施；以下补充规则为本计划的建议默认值，尚非已经验证的产品结论。

## 1. 需求充分性结论

**现有需求足够启动实施。** 世界结构（单城沙箱+身世轻主线）、六维数值与战斗公式草案、三层成长机制、武学体系、四维生存、结局双轨、轮回继承、UI 修复项均已明确。技术底盘复用 v1.0（事务/幂等/SSE/provider 抽象/mock 流程），重写游戏层。

尚不是完整实现规格的部分：事件/武学/NPC 的具体文案、战斗数值的平衡、事件抽取的手感。这些按第 2 节默认规则落地，用真实试玩调参，不阻塞启动。真实模型能力仍需 key 到位后验证（沿用 v1.0 遗留项）。

## 2. 实施前统一的规则

| 问题 | 建议默认规则 |
| --- | --- |
| 时间粒度 | 每天 4 个行动时段（晨/午/昏/夜），行动消耗 1 时段；「过一日」一键消耗剩余时段；时段归零自动进入次日；一年 360 天、四季各 90 天，换年年龄 +1。年龄 16 岁开局 |
| 温饱 | 温饱 0~10，每 2 时段 -1；「用饭」行动恢复 4（耗银两）；温饱=0 起每天 HP -2 并投放困境事件；连续断粮 3 天可饿死 |
| 战斗触发 | 仅由事件结果/敌对遭遇触发（数据里显式声明），不做野怪随机遭遇 |
| 战斗先手 | 敏捷高者先行动，同值玩家先 |
| 战败后果 | 敌人标注 `lethal` 时 HP=0 即死亡；否则重伤（HP 降至 1、生命上限临时 -50%，痊愈需医伤/静养）；逃跑为敏捷对抗，失败被击一次 |
| 真气恢复 | 战斗每回合恢复 1+内功等级；「防御」指令额外 +2；非战斗「打坐」按内功等级恢复 |
| 衰老 | ≥60 岁每 5 年武力/敏捷 -1；内功大成（三等级满）免疫；≥70 岁可善终 |
| LLM 小额成长 | 单次 ≤1 点、理由标签必须与行动类别匹配、**每日至多 1 次**、违规整份拒绝→重试一次→降级（沿用 v1.0 三关+重试预算模式） |
| 事件抽取 | 每次行动结算后按 触发条件+权重 抽取至多 1 个事件；同一事件 30 天冷却；身世主线事件走链路触发、不进随机池 |
| 结局检查 | 每次结算后代码静默检查达成型条件表；多结局同时命中取 `priority` 高者；选择型结局在基础条件满足后作为行动选项出现 |
| 轮回结算 | 死亡或结局 → 记忆提炼（一次 LLM 调用，失败不阻塞）→ 武学图谱更新 → 出身解锁 → 履历入库 → 新一世出身选择 |
| 武学跨世 | 已领悟武学（含等级）直接可用；未领悟武学的属性习得门槛在后续世 -1（前世见识） |
| 世界重置 | 新一世：NPC 恩怨/势力关系/声望/银两/温饱全部重置为出身初始态；世界日历重置 |
| 战斗演绎 | 引擎结算后每回合一次 LLM 演绎调用（≤150 字短叙事，无数值权）；mock 模式用模板文本；演绎失败降级为模板战斗日志，不阻塞战斗 |
| mock 命令 | 升级为 `/battle 敌id`、`/grow 武力`、`/event 事件id`、`/money ±n`、`/rep ±n`、`/age n`、`/bad-json`、`/bad-grow` 等；支持可控敌人与必胜/必败脚本 |
| 存档迁移 | SQLite `user_version=2`：游戏表结构不兼容 v1.0，直接重建（v1.0 存档不保留，README 声明）；requests/turn_logs/usage/events 表结构沿用 |
| 单活跃一世 | 同 v1.0：一个活跃 life；历代履历只读；刷新恢复快照；requestId 幂等 + 版本校验沿用 |

## 3. 工程与模块边界

- `packages/core`（重写）：状态类型（LifeState/BattleState/Calendar/图谱/履历）、常量表（时段/公式/概率/冷却/衰减）、`calendar`（时段/季节/年龄）、`battle`（纯函数战斗引擎+敌方行为倾向）、`growth`（三层成长与校验）、`events-engine`（条件抽取+冷却，事件定义由外部注入）、`endings`（条件表判定）、`inheritance`（轮回结算）、`memory`（沿用 v1.0 纯函数）
- `packages/worlddata`（重写）：单城世界库——`world`（地点/势力/日历事件）、`npcs`（12 人+恩怨钩子）、`events`（50 条：条件/选项/结果/战斗引用/后续链）、`martial`（26 门武学：档位/类别/门槛/数值/特效）、`origins`（4 初始+可解锁）、`destinies`（3 条身世线）、`endings`（12 结局+条件表）、`checks`（完整性检查：条件引用有效、武学门槛可达、结局可达、事件链无死链）
- `packages/llm`（增强）：新 schema（行动演绎、战斗演绎、结局章、记忆提炼）；prompt 构建（注入地点/季节/年龄/六维/银两/恩怨/武学/前世记忆/摘要）；provider/流式扫描/重试执行器沿用
- `apps/server`（保留底盘）：DB 迁移 v2、`GameService` v2（life/act/battle/settle/history/memory）、路由新增 `POST /api/lives/:id/act`、`POST /api/lives/:id/battle/turn`、`GET /api/lives`（轮回历史）、出身/世界目录 API；事务、幂等、版本校验、SSE 沿用
- `apps/web`（保留底盘）：视图重构——出身选择、一世主界面（行动菜单+自由输入+事件演绎流+六维/生存侧栏）、战斗面板（双血条/真气条/武学按钮/回合日志）、结局章、轮回历史页；自动滚屏（手动上滚暂停、回底恢复）

统一 zod schema 与 TS 类型，模型名/超时/数值/限额全部走配置与常量表。

## 5. 验收矩阵

| 需求/补充检查 | 验证方式与预期 |
| --- | --- |
| 成长因果（比武胜→武力、解谜→智力） | 跑对应事件断言属性变化；LLM 申报 `吃饭→武力` 类被整份拒绝 |
| 战斗公式 | 单测：伤害=武力×倍率×等级系数−防御（下限 1）；暴击×1.5；闪避区间；真气不足拒绝出招；逃跑成败分支；lethal 死亡 vs 重伤 |
| 武学体系 | 门槛不足不可习得；机缘事件习得；等级提升改变数值；绝学无法跳级；跨世含等级保留、未领悟门槛 -1 |
| 轮回继承 | 死后第二世：武学可用、prompt 含记忆且叙事引用（真实模型留样）、解锁出身可选；恩怨/银两/声望重置 |
| 结局双轨 | 达成型静默触发（构造条件）；选择型满足条件后出现于行动；多结局取 priority；善终（≥70 岁）可达 |
| 生存压力 | 断粮 3 天死亡路径；温饱/银两在行动中正确流转；医伤恢复重伤状态 |
| 时间与衰老 | 时段→日→季→年推进；≥60 岁每 5 年衰减；内功大成免疫 |
| LLM 异常 | 坏 JSON/非法成长/超时注入：重试一次→降级；战斗演绎失败走模板日志；存档可恢复 |
| 重复请求/结算幂等 | 相同 requestId 同结果；并发不覆盖快照；settle/memory retry 不重复发奖 |
| 事件系统 | 冷却期内不重复抽取；条件不满足不出现；主线事件不进随机池；checks 全过 |
| 战斗分布 | 模拟器 ≥100 场：无首回合秒杀、平均 3~8 回合 |
| UI 滚屏 | 追加自动滚底；上滚暂停、回底恢复（手测） |
| 轮回历史 | 每世履历含 出身/生卒/死因或结局/武学/时间线（集成测试 + 手测） |

## 6. 执行顺序与风险控制

依赖：**P0 → P1 → P2 → P3 → P4 → P5**。P2 完成即可用 mock 跑通全循环（垂直切片），P1 的内容补齐（20→50 事件）与 P3/P4 并行推进。

主要风险与对策：战斗数值失衡（模拟器分布测试+常量表调参）；演绎与引擎结算脱节（prompt 明确结算记录为唯一事实）；事件内容制作量（先 20 条验证手感再补齐）；LLM 成长滥用（日上限+类别校验+拒绝即降级）；生存节奏拖沓（随机遭遇率+季节节点+「过一日」）；真实模型未验证（延续 v1.0 遗留，key 到位后补）。

本计划只安排开发与验证。当前任务到计划落盘为止，不开始实施代码。
