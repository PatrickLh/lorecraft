# LoreCraft 需求文档 v2.0 —— 江湖一生

> **武侠生存模拟 × LLM 动态叙事 × 代码权威战斗 × 无限轮回**

---

## 0. 背景：v1.0 为什么不好玩

v1.0 试玩结论（2026-10-11）：

1. **三个脱节的剧本世界不是无限流，是三个章节**——世界之间没有连续感，"穿梭"只是换地图
2. **寿命数值与题材零咬合**——寿命、体质/心智/敏捷既无叙事意义，也无成长反馈
3. **没有"变强"的实感**——无战斗、无武学、无属性成长，文字冒险退化成阅读器
4. **交互缺陷**——对话后不自动滚屏；无轮回历史可查

v2.0 的答案：**只做一个低武世界（金庸/古龙/梁羽生式江湖），把无限轮回装进同一个世界里**。玩家是一介小虾米，在沙箱江湖中生存、习武、结怨、扬名，直至死亡或善终；带走武学与记忆，转世重来。本质是**生存模拟 roguelite**。

## 1. 定位

- 个人原型（延续 v1.0），验证核心问题：**「代码权威生存模拟 + LLM 演绎」能否让"一世人生"好玩**
- 不做账号、付费、多用户；技术底盘完全复用 v1.0（monorepo / Hono+SQLite / Vue3 / provider 抽象 / mock 流程 / 幂等事务 / SSE）

## 2. 核心循环

```
        ┌─────────────── 结算继承（武学/记忆/出身解锁）───────────────┐
        ▼                                                            │
  选出身 → 一世开局（属性/银两/年龄 16 岁）                             │
        │                                                            │
        │   ┌─────────────── 一世（沙箱生存）───────────────┐         │
        │   │  行动菜单/自由行动（各耗时辰）                  │         │
        │   │  → 随机遭遇（手写事件库按条件抽取）             │         │
        │   │  → 战斗（代码引擎结算，LLM 演绎）               │         │
        │   │  → 成长（三层混合机制）                         │         │
        │   │  → 结局检查（达成型静默判 / 选择型主动触发）     │         │
        │   └────────────── 死亡 或 结局 ────────────────────┘         │
        │                               │                              │
        └───────── 死亡记忆提炼 ←───────┘──────────────────────────────┘
```

- **一世**：16 岁出身开局，年龄随时间推进，直至死亡或达成结局
- **轮回**：结算继承 → 选出身（可选用已解锁出身）→ 新一世。**世界是同一个，Npc/势力/恩怨在新一世重置为初始态**（记忆里记得上一世的他们）

## 3. 六维数值体系（展示面板）

| 属性 | 作用 | 初始（小虾米基准） | 成长来源 |
|------|------|------|------|
| 生命 HP | 归零即死；受伤扣减，休息/医伤回复 | 30 | 等级成长小增；医伤/休养 |
| 真气 MP | 释放武学的消耗资源；每回合引擎回复少量 | 10（无内功） | **内功**提升上限与回复 |
| 武力 | 伤害基础值 | 5 | 比武/战斗胜、练武、名师指点、秘籍 |
| 防御 | 抵消伤害 | 3 | 练武（外功）、护甲、横练功夫 |
| 智力 | 武学习得门槛、解谜 | 5 | 读书、解谜、交谈论道 |
| 敏捷 | 闪避率、暴击率、轻功加成 | 5 | 练武（身法）、轻功、江湖历练 |

- 属性成长**只由事件触发**，必须因果成立：比武获胜→武力；解谜→智力；轻功逃亡成功→敏捷
- 数值框架（初值，集中于常量表调参）：伤害 = `武力 × 武学倍率(1.0~2.5) × 等级系数(入门1.0/小成1.3/大成1.6) − 敌方防御`，最低 1；暴击 ×1.5（暴击率 = 敏捷相关 5%~25%）；闪避率 = 双方敏捷差 × 3%（5%~30%）
- **衰老**：60 岁起每 5 年武力/敏捷 −1（内功等级可延缓）；寿终正寝（≥70 岁）是「善终」结局而非失败

## 4. 战斗系统（代码权威）

- **进入战斗**：事件结果或敌对遭遇触发，切换到战斗模式（独立面板）
- **每回合玩家指令（纯按钮）**：已学武学（受真气限制）/ 普通攻击 / 防御（减伤+回气）/ 逃跑（敏捷对抗，失败挨一击）
- **结算**：引擎按 §3 公式计算双方动作结果（敌方 AI：手写行为倾向——猛攻/防御/用毒等），输出回合结算记录
- **演绎**：LLM 把引擎结算结果写成战斗叙事（不含任何数值决定权，dangerProposal 机制废除）
- **胜负后果**：胜利→战利品/声望/成长申报（§5）；失败→重伤（生命上限临时受损）/被俘/死亡，视敌人下手轻重
- 敌人数据手写在事件/NPC 定义里（兵力值化：武力/防御/敏捷/生命/行为倾向）

## 5. 成长机制（三层混合，保证"合理性"）

1. **手写事件自带成长**：事件定义的选项结果直接携带成长（`比武得胜` 事件 → 武力+1），代码结算
2. **固定修炼行动**：行动菜单内置 练武（武力/防御，小概率）/ 读书（智力）/ 打坐（真气上限微增，需内功）/ 练轻功（敏捷）——每次耗时辰+银两/温饱消耗
3. **LLM 自由事件小额申报**：不在预设事件内的自由行动，LLM 可申报成长，但**单次 ≤1 点、必须携带理由标签、标签须与行动类别匹配**（`武力` 只接受战斗/练武类理由），违规整份拒绝→重试→降级（沿用 v1.0 三关校验+降级模式）

里程碑成长（+2~3 点，如名师传功、奇遇秘籍）只来自手写事件，LLM 永远无权。

## 6. 武学系统

- **手写武学库 26 门**，四档：三流（10）/ 二流（8）/ 一流（6）/ 绝学（2）
- **分类**：拳掌 / 剑法 / 轻功 / 内功 / 奇门
  - 攻击类（拳掌/剑/奇门）：真气消耗、伤害倍率、等级特效（破防/连击/吸血/反击）
  - 内功：真气上限+每回合回复，衰老延缓
  - 轻功：闪避率加成、逃跑成功率
- **三等级**：入门 / 小成 / 大成（修炼行动+机缘提升），等级影响倍率/特效
- **习得条件**：属性门槛（如一流剑法需智力 ≥12 且剑法基础）+ **机缘事件**（秘籍/名师/观摩），写入事件库；门槛不足时事件不出现或强行修炼有走火入魔风险
- **轮回保留**：已领悟武学跨世保留（含等级），新一世重新拜师/寻秘籍可快速重修（习得条件减半）

## 7. 生存模拟维度

| 维度 | 机制 |
|------|------|
| 银两 | 通用资源：食宿、买武学、医伤、打点官府、赏金、拜师礼 |
| 温饱 | 每日消耗，不进食→生命持续流失并触发困境事件；住宿品质影响恢复 |
| 声望 | 侠名/凶名单轴：影响 NPC 初始态度、事件解锁、结局分支 |
| 门派/势力 | 4 势力：可拜入门派（任务/武学/庇护/门规约束）、官府、绿林、商会；关系值决定敌友与事件 |
| NPC 恩怨网 | 12 名关键 NPC（师徒/挚友/宿敌/红颜/权贵），各有好感/仇恨值；恩怨影响剧情、战斗（仇家寻仇）、结局 |

## 8. 世界与内容（单城 MVP）

- **地理**：一城（坊市/码头/贫民窟/衙门/城郊野林），行动在地点间移动
- **势力**：1 个可拜入门派 + 官府 + 绿林 + 商会
- **NPC**：12 名关键人物（手写：性格/武学/恩怨钩子）
- **事件库**：50 条手写事件（触发条件：地点/季节/身份/属性/关系/概率；选项 2-4 个；结果携带 §5 成长/物品/关系/战斗触发/后续事件链）
- **身世轻主线 3 条**（家传秘笈之谜 / 灭门之仇 / 身世之谜）：开局随机或选出身附带，有大奖励，不做不影响世界运转
- **出身 4 种**（初始）：农家子 / 市井游儿 / 商行学徒 / 军户子弟（各有属性/银两/初始恩怨偏向）；**可解锁出身**：前世达成的身份（如门派内门弟子）作为新起点
- **季节运转**：每 90 天一季；季节事件（春季大比、年关市集、仇家寻衅）由代码按日历投放
- **结局 12 个（手写）**：达成型（武功天下第一/开宗立派/武林盟主/富甲一方/官居四品/名动江湖/魔道巨擘…）+ 选择型（退隐山林/远走海外…，满足基础条件后作为行动出现）+ 死亡结局（战死/死于非命/饿殍/寿终正寝=善终）

## 9. 轮回与继承

死亡或结局后：

1. **记忆提炼**（LLM，一次调用）：本世浓缩为 ≤5 条记忆（恩怨、秘笈下落、教训、路线），总量封顶 20 条，注入下一世 prompt
2. **武学保留**：已领悟武学与等级原样带入
3. **出身解锁**：本世达成的身份进入出身池
4. 属性/银两/关系/恩怨**全部重置**；世界回到初始态
5. 下一世 prompt 中，LLM 被要求在叙事中自然引用前世记忆（"你前世死于此人之手……"）

## 10. 交互与 UI

- **非战斗**：自由文本 + LLM 建议行动按钮 + 固定行动菜单（练武/做工/游历/打听/用饭/住宿/修炼内功…）
- **战斗**：独立面板——双方生命/真气条、武学按钮组、回合日志
- **修复：自动滚屏**——新叙事追加时日志自动滚动到底部（用户手动上滚时暂停，回底恢复）
- **新增：轮回历史页**——每世一条履历（出身/生卒年/死因或结局/属性峰值/习得武学/关键事件时间线/达成结局），可回看历代
- 六维+银两+声望+温饱+身份 常驻侧栏面板

## 11. LLM 架构（沿用 + 收缩）

- 沿用 v1.0：provider 抽象（mock/DeepSeek/Claude）、单次调用大 schema、结构化输出、重试一次+降级、滚动摘要、SSE 流式、mock 斜杠命令
- **收缩**：战斗数值、事件奖励、结局判定全部由代码结算，LLM 的申报范围只剩：自由行动小额成长（≤1 点+理由标签）、关系变动提议、物品命名、事件演绎、战斗演绎（无数值权）、结局章演绎、记忆提炼
- prompt 注入：世界设定、当前地点/季节/年龄、权威状态、恩怨关系、已学武学、前世记忆、近期摘要
- mock provider 同步升级：支持新 schema 与斜杠命令（`/battle`、`/event ev_id`、`/grow武力` 等）

## 13. v2.0 范围与验收标准

**范围**：单城 MVP 内容量（§8）+ 完整循环：选出身 → 生存 ≥1 年 → 至少经历 1 场战斗、习得 ≥1 门武学、触发 ≥1 次成长 → 死亡或结局 → 继承 → 第二世感知增强。

**验收标准**：

1. ✅ 一世内：比武获胜 → 武力 +1（面板可见）；解谜事件 → 智力 +1（因果成立）
2. ✅ 战斗：代码引擎结算，伤害符合 §3 公式（测试覆盖：暴击/闪避/防御减免/真气不足拒绝/逃跑）
3. ✅ 武学：满足门槛+机缘习得；等级提升改变战斗数值；绝学无法跳级习得
4. ✅ 轮回：死后第二世——武学保留、记忆注入 prompt 且被叙事引用、解锁出身可选
5. ✅ 结局：达成型结局被条件表静默触发；选择型结局在条件满足后可被选中；善终（≥70 岁）可达
6. ✅ 生存压力：断粮断银触发困境；温饱/银两/声望/恩怨数值在事件中正确流转
7. ✅ UI：叙事自动滚屏；轮回历史页可查每一世履历
8. ✅ LLM 异常：沿用 v1.0 降级路径，游戏不崩溃

## 14. 明确不做（Non-goals）

- 多世界/世界穿梭（v1.0 概念废弃）
- 骰子/检定规则系统（战斗是确定性公式，不是 COC 式判定）
- 武学熟练度外的复杂养成（装备打造、丹药炼制、暗器谱等留 v3）
- 大地图/多城、骑乘/轻功赶路系统
- 账号/付费/多用户/移动端/i18n

## 15. 风险与对策

| 风险 | 对策 |
|------|------|
| 战斗公式数值失衡（秒杀/刮痧） | 全公式集中常量表；敌人数值随档位标定；用 mock 自动跑 100 场战斗分布测试 |
| 50 条事件的内容制作量 | 先做 20 条撑起单城一年生存，验证循环后补齐 |
| LLM 演绎与引擎结算脱节（叙事说打中但引擎闪避了） | prompt 明确"以结算记录为唯一事实"，演绎只是修辞 |
| NPC 恩怨网复杂度失控 | 12 人封顶；关系值只做单向好/恶两轴；事件引用而非自由演变 |
| 生存模拟节奏拖沓（行动→吃饭→睡觉无聊） | 时辰推进有随机遭遇率；季节事件制造节点；行动菜单一键多步（"过一日"） |

## 附：v2.0 关键决策记录（2026-10-11 grilling）

1. 单一低武世界（金庸/古龙式），废弃三世界穿梭
2. 轮回继承 = 武学保留 + 前世记忆 + 出身解锁（无先天资质）
3. 时间 = 年龄+季节推进；善终是结局不是失败
4. 战斗 = 代码权威引擎（公式结算），战斗中纯按钮指令
5. 武学 = 手写 26 门四档 + 三等级，门槛+机缘习得
6. 成长 = 三层混合（手写事件 / 修炼行动 / LLM 小额申报≤1 点带理由标签）
7. 生存维度 = 银两温饱 + 声望 + 门派势力 + NPC 恩怨网（全选）
8. 叙事结构 = 沙箱 + 身世轻主线（不强制）
9. 结局 = 条件表（静默达成）+ 主动选择双轨，12 个手写结局
10. 内容量 = 单城 MVP：4 势力/12 NPC/50 事件/3 身世线/4+出身
11. 技术 = 复用 v1.0 底盘，重写游戏层
